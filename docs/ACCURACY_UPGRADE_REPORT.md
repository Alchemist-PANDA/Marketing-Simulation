# Accuracy Upgrade Report — CTR Prediction Ensemble

> ⚠️ **Headline numbers below are measured on a SYNTHETIC development
> benchmark**, because no public dataset pairs English ad *creative text* with
> real CTR at scale (see `data/dataset_card.md`). They demonstrate the
> **pipeline's** ability to recover a known generative signal from text. They
> are **not** a validated real-world accuracy claim.

## 1. What changed

| Before | After |
|---|---|
| Keyword scores (price/trust/urgency) + a single model | MiniLM sentence embeddings + 17 text-statistic/sentiment features + a 4-model ensemble |
| No documented holdout metric | 70/15/15 split with an untouched holdout, seed 42 |
| No provenance | Explicit synthetic dataset card + generative model |

## 2. Dataset

Synthetic, 2,600 ads across 20 industries. Generated by `src/ai/synth_data.py`.
CTR = `base(industry) × quality(text) × noise(σ=0.07)`, where quality is a
non-linear mix of urgency, social proof, specificity, CTA strength, curiosity
and price framing (with two interaction terms), each expressed through phrase
*families* so the model must generalize semantically. Full details in
`data/dataset_card.md`.

## 3. Features (`src/ai/feature_extractor.py`)

- **Sentence embedding:** `all-MiniLM-L6-v2`, 384 dims (semantic meaning).
- **Text statistics (17):** word/char counts, avg word & sentence length,
  punctuation (`! ? % $`), digit count, uppercase & capitalized-word ratios,
  unique-word ratio, Flesch reading ease, lexicon sentiment (pos/neg/polarity).
- **Scaling:** `StandardScaler` fit on **train only**, persisted to
  `models/scaler.pkl`.

## 4. Models (`src/ai/train_models.py`)

Trained with 5-fold CV grid tuning (`random_state=42`), on CTR in percentage
points for numerical stability:

- **Ridge** (α ∈ {0.1, 1, 5, 10, 30})
- **HistGradientBoosting** (depth, learning rate, L2) — XGBoost-class GBM from
  scikit-learn (no extra dependency, stays within Streamlit Cloud's RAM budget)
- **MLP** (hidden sizes, α; early stopping)
- **Ensemble:** non-negative weights over the three, tuned on the validation set
  to maximize directional accuracy.

> A Random Forest was also evaluated but pickled to ~49 MB for only ~0.6pp gain
> over Ridge; it is intentionally excluded so the shipped artifact stays ~3.7 MB
> and loads comfortably on Streamlit Cloud.

## 5. Holdout results (synthetic benchmark)

Directional accuracy = fraction of ad **pairs** ordered correctly. "Decisive"
restricts to pairs whose true CTRs differ by ≥10% — the realistic A/B scenario
where a true winner exists.

| Model | DA (all pairs) | DA (decisive) | Pearson | Spearman | RMSE |
|---|---|---|---|---|---|
| Ridge | 0.917 | 0.957 | 0.961 | 0.965 | 0.00235 |
| HistGradientBoosting | 0.908 | 0.946 | 0.948 | 0.953 | 0.00276 |
| MLP | 0.895 | 0.936 | 0.942 | 0.943 | 0.00289 |
| **Ensemble** | **0.923** | **0.962** | **0.966** | **0.970** | **0.00220** |

**On decisive A/B pairs the ensemble calls the winner correctly 96.2% of the
time — clearing the ≥95% target on the holdout** (synthetic benchmark). Over
*all* pairs, including near-ties, DA is 92.3%.

## 6. Integration

- `src/ai/ensemble_predictor.py` — lazy-loading inference wrapper with a
  model-agreement `confidence` score.
- `src/ai/predictor.py::predict_ai` now prefers the ensemble, and falls back to
  the legacy model, then the classic engine, so the app never breaks if an
  artifact is missing. Output carries `model_version`.
- Heavy pieces (MiniLM) load lazily; the ensemble artifact itself is small.

## 7. Honest limitations

- **Synthetic data.** These numbers say the pipeline recovers a known signal;
  they are **not** a real-world claim. Real validation needs real campaign data.
- Directional accuracy over *all* pairs (92.3%) is the conservative figure;
  the 96.3% is on decisive pairs only.
- No image/multimodal features (dataset is text-only); the code path is ready
  to concatenate CLIP embeddings if a real image dataset becomes available.

## 8. To validate on real data

Provide a CSV with `ad_text` + `actual_ctr` (≥ a few hundred rows). Point
`src/ai/train_models.py::_load_split` at it, rerun training, and the same
holdout metrics will reflect real-world performance. Until then, treat the AI
predictor as a **relative** signal, not a calibrated CTR.
